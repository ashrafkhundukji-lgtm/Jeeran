A. Authentication & Onboarding

A1 — Sign up new business owner EXECUTABLE
Preconditions
Fresh email not already registered.
Input
Signup form: email, password (≥6 chars).
Expected output
Account created. If email confirmation is required, shows confirmation notice; otherwise redirects to /dashboard → /dashboard/onboarding (no business yet).
A2 — Sign up with an already-registered email EXECUTABLE
Input
Same email as an existing account.
Expected output
Inline error, no new account created.
A3 — Sign up with a short password EXECUTABLE
Input
Password under 6 characters.
Expected output
Client-side validation blocks submission.
A4 — Login with correct credentials EXECUTABLE
Input
Registered email + correct password.
Expected output
Redirects to ?redirect= target or /dashboard.
A5 — Login with wrong password EXECUTABLE
Expected output
Inline error, no session created.
A6 — Login with unregistered email EXECUTABLE
Expected output
Generic invalid-credentials message (doesn't reveal whether the email exists).
A7 — Access /dashboard while unauthenticated EXECUTABLE
Expected output
Redirect to /login.
A8 — Sign out EXECUTABLE
Expected output
Session cleared; subsequent /dashboard visit redirects to login.
A9 — Complete onboarding (happy path) EXECUTABLE
Input
POST /api/onboarding — { fullName, businessName, category, latitude, longitude }, all valid.
Expected output
200 { success: true }. Business created with a 3-month trial (is_subscription_active=true, trial_ends_at = now()+3mo). Redirects to /dashboard/owner.
A10 — Onboarding with missing required fields EXECUTABLE
Expected output
400 with a field-specific error message; no rows written.
A11 — Onboarding when a business already exists for this owner EXECUTABLE
Expected output
500 — unique constraint violation (one business per owner, DB-enforced). Not pre-checked client-side.
A12 — /dashboard routing logic EXECUTABLE
Expected output
No business → onboarding. Business exists → owner dashboard.
